# 发票整理与报销说明

按已经确认的个人报销整理规则完成材料归档和 Word 说明。一个工作区对应一个项目，支持多人报销；正式说明按类别和用途汇总。

## 随附资源

- [整理规则](references/整理规则.md)：在整理文件和判断待补材料前读取。
- [Word 填写与更新](references/Word填写与更新.md)：生成或更新说明时读取。
- `assets/报销内容简要说明.docx`：通用 Word 母版，作为只读参考使用。
- `assets/母版预览.png`：母版的页面外观参考。
- `assets/信息采集表.md`：用户希望集中填写资料时提供的可选表格。

本 Skill 存放于项目的 `.agents/skills/expense/`，资源路径相对于本 Skill 所在目录。使用当前 Agent 环境可用的 Word/DOCX、PDF 和图片工具；环境提供 documents、PDF 等技能时按需复用。按所用工具的要求定位依赖和运行时。

## 先收集信息

使用时先收集以下信息，当前对话已经明确的值直接复用，缺项和冲突向用户询问。

1. 用户姓名，用于命名工作区目录。
2. 项目编号和项目名称。
3. 发票所在目录，以及每张发票所属的报销人姓名。单人批次可由用户统一确认归属，多人批次逐张或分组确认。

姓名、项目资料和人员归属以用户答复为准。可以先只读查看材料，帮助用户用文件名或发票号码回答；有待确认的姓名和金额进入待补清单。

开场问题示例：请提供本次使用者姓名、项目编号、项目名称，以及发票所在目录；多人报销时，请同时说明各张发票的人员归属。

## 执行流程

### 建立工作区

工作区是存放本次报销材料的根目录，以用户提供的姓名命名，例如 `张三/`。按用户指定位置创建或整理该目录，保持四个固定目录，即使目录为空也保留。

```text
用户姓名/
├─ 发票/
├─ 订单截图/
├─ 付款记录/
├─ 历史备份（旧版本，忽略）/
└─ 报销内容简要说明.docx
```

已有明确指定的报销工作区可按姓名重命名；上层目录还包含其他项目时，在该位置建立姓名目录，归入用户指定的本次材料。多个报销人的发票共同放入本项目工作区，发票文件名使用各自所属人员的姓名。

同名工作区属于相同项目时继续使用；同名工作区属于其他项目时，请用户指定新的父目录，保留以姓名命名的规则。

### 识别和整理材料

先确认用户这次指定的目录，再读取其全部有效材料。扫描跳过 `历史备份（旧版本，忽略）` 及系统临时文件。

从每张发票核对发票号码、物品或服务、价税合计。建立发票与人员、订单截图、付款记录的对应关系，按整理规则直接重命名已确认的文件。保留 PDF 和图片内容，采用可避开重名的写入方式。

根据发票号码标记重复关系，文件保留，同一票号的内容在说明中纳入一次。同名同金额且票号不同的发票分别纳入，再合并同类用途。

### 集中补充材料和确认用途

按整理规则判断每张发票需要的材料。先完成已具备信息的发票整理，再集中提供待补清单，按文件名或票号列出缺少的人员归属、订单截图、付款记录、采购原因和事实疑点。

根据项目资料及实际发票拟写分类用途，同类物品合并表达，在对话中集中请用户确认。实物特殊采购的“无京东自营”原因由用户逐项提供；服务类特殊采购向用户询问实际原因。采购事实以用户原文为依据，措辞可适度整理。

材料收齐、用途确认后生成正式说明。等待必要答复期间保留已有正式文档和已完成的整理结果，向用户说明具体待补项。

### 生成说明

按 [Word 填写与更新](references/Word填写与更新.md) 使用母版生成 `报销内容简要说明.docx`，写入姓名工作区的根目录。

多人发票生成一份说明，保留项目资料、分类用途、价格总计和本次实际需要的特殊采购说明。正文省略按人分组、人员明细和个人小计。在全部报销明细之后、特殊采购说明之前写入价格总计，按发票号码去重后汇总本次有效发票的价税合计，金额保留两位小数。用户提供特殊采购佐证图片时，嵌入对应说明下方；图片为可选材料。

## 新增发票和更新

用户新增发票后，重新读取当前工作区的全部发票，按票号处理重复，重新计算价格总计，并保留现有说明中已确认的用途和采购原因。新增或需要更改的内容集中请用户确认，已有准确内容直接沿用。

写入更新版之前，把当前说明备份至 `历史备份（旧版本，忽略）/报销内容简要说明-YYYYMMDD-HHmmss.docx`。采用本次操作的本地时间，同名追加序号。其他明确属于旧版本的文档和材料也归入该目录。

## 交付

生成前检查必需信息和材料已收齐，确认母版字段全部处理，并使用可用的文档渲染工具查看每一页。完成后简短给出姓名工作区、正式 Word 的绝对路径，以及重复关系等需要知晓的情况。

存在待补项时，交付已完成的整理结果及具体清单，收齐后继续生成正式说明。
